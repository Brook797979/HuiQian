## 1. 项目概述

**慧签** 是一套**低成本、可离线运行、双因子（指纹+人脸）防代签**的智能考勤系统。

针对的现实痛点：
- 传统打卡（点名/刷卡/手机定位）**容易被代签、代打卡**；
- 纯人脸考勤**防不了"拿照片/视频"作弊**（没有活体检测）；
- 课堂/实验室/车间等场景**可能没有稳定网络**，云端方案不可靠；
- 商用考勤终端**价格高、不开放、难二次开发**。

慧签的答案：用 **K210（约几十元）做端侧人脸检测 + 树莓派 5 做识别核心 + AS608 指纹模块做第二因子 + 自制蓝牙音箱语音播报 + 微信小程序看数据**，组成一条完整闭环，并且**完全离线也能用**。

## 3. 硬件组成与原理

### 3.1 嘉楠 K210（Sipeed M1 开发板）—— 端侧触发端
- **芯片**：嘉楠 Kendryte K210，双核 RISC-V 64 位，主频 400MHz，带 **KPU（神经网络处理器）**，6MB 片上 SRAM。
- **为什么选它**：便宜（几十元）、自带 KPU 可跑轻量神经网络（我们用它跑 **YOLO2 人脸检测**）、自带摄像头接口、LCD、低功耗（约 1W），适合做"端侧第一道感知"。
- **板载外设**：摄像头（OV2640，QVGA 320×240）、LCD 屏（320×240）、蜂鸣器、按键、UART 串口。
- **本项目中 K210 的角色**：只做**人脸检测（有无人脸、框在哪）** + 现场交互（菜单/提示/蜂鸣器），**不做人脸身份识别**（识别太重，交给树莓派）。检测到人脸 → 通过串口通知树莓派。

> 名词解释：**KPU** 是 K210 芯片里的神经网络加速器，可以理解为"给 AI 推理用的专门计算单元"，跑 YOLO 这类模型比 CPU 快很多。

### 3.2 树莓派 5 —— 核心计算端
- **CPU**：ARM Cortex-A76 四核 2.4GHz，内存 8GB，跑完整 Linux（Raspberry Pi OS）。
- **CSI 摄像头**：OV5647，最高 1080p。本项目用它**抓拍打卡者照片、做人脸识别**（720p 就够，速度更快）。
- **为什么识别放树莓派**：人脸身份识别（128 维特征提取）计算量大，K210 跑不动；树莓派上可跑成熟的 MediaPipe + dlib/face_recognition，准确率高、开发快。
- **音频**：树莓派 5 **没有 3.5mm 耳机口**，声音走 **USB 音箱**或**蓝牙音箱**。我们用自制的蓝牙音箱（蓝牙 A2DP 协议）。

### 3.3 AS608 光学指纹模块 —— 第二认证因子
- **原理**：光学指纹传感器。手指按在玻璃面上，传感器拍照得到指纹图像，模块内部算法提取**指纹特征点（端点、分叉点等）**，生成**模板（template）**。
- **存储**：AS608 模块内部 flash 有 160 个**槽位（1~160）**，每个槽位存一个指纹模板。
- **通信**：串口（UART），波特率 **57600**，指令包格式（帧头 0xEF01 + 地址 + 包标识 + 校验和）。
- **本项目用法**：
  - **录入**：按 2 次手指 → 分别生成模板 → 模块内部合并（RegModel）→ 存入槽位；
  - **比对**：按手指 → 采图 → 生成模板 → 和库内模板搜索匹配（1:N），返回槽位号；
  - 数据库只存 **fp_id（槽位号）→ 用户** 的映射，模板本身存在模块里。

### 3.4 USB 转 TTL（CH340）—— 串口桥接
- K210 和 AS608 都是 TTL 串口设备，树莓派是 USB 口，所以用 **CH340 USB-TTL 模块**转接。
- 一块接 K210（115200），另一块接 AS608（57600）——**串口设备在 Linux 里显示为 /dev/ttyUSB0、/dev/ttyUSB1**。

### 3.5 自制蓝牙音箱（语音播报）
- 团队自制的蓝牙音箱（MH-M18 蓝牙模块 + 功放 + 4Ω/3W 喇叭），通过**蓝牙 A2DP 协议**接收树莓派播放的语音。
- 树莓派侧：pygame → ALSA → **BlueALSA（bluealsa）** → 蓝牙音箱。开机自动配对连接。

## 4. 核心技术原理

### 4.1 人脸检测（K210 端：YOLO2）
- YOLO 是"单阶段目标检测"算法，一次前向推理同时输出**目标类别 + 位置框**。
- K210 上跑的是**训练好的 YOLO2 人脸检测模型**（存在 flash 0x300000，用 `kpu.load` 加载到 KPU）。
- 输入 QVGA 图 → KPU 推理 → 输出若干候选框 + 置信度 → 阈值过滤 → 得到"有没有人脸、在哪"。
- 这个模型只回答"是不是人脸"，**不回答"是谁"**。

### 4.2 人脸识别（树莓派端：特征向量 + 距离比对）
- 用 **MediaPipe FaceDetector** 检测人脸框 → **FaceLandmarker** 标出 478 个关键点 → 裁剪人脸 → 用 **face_recognition（dlib 后端）** 提取 **128 维特征向量**。
- **特征向量 = 人脸的"数字指纹"**：把一张脸压缩成 128 个数字，同一个人不同角度/光照下，这 128 个数字"差不多"；不同人差别大。
- **比对方式**：算两个向量的**欧氏距离**（`face_distance`），距离 < 阈值（0.6）判为同一个人。
- **容错策略**：HOG 提特征失败就多尺度重试，再不行用 CNN 兜底（对角度/大小更稳，但慢）。
- 每个人的 3 张照片特征都存数据库，打卡时和库里所有人比对（1:N）。

### 4.3 活体检测（防照片/视频作弊）
- **方案一：摇头检测**（当前启用）。用 MediaPipe 关键点里的**鼻尖点**，抓拍连续帧记录鼻尖 x 坐标，判断是否**左右摆动**（幅度够大 + 方向反转够多次）。真人的头会晃，照片不会。
- **方案二：眨眼检测（EAR 算法）**。眼睛关键点算 EAR（眼睛纵横比），数值小=闭眼。真人会眨眼，照片/视频里不会。
- 这就是"活体检测"——确保面前是**真人**而不是一张照片/一段视频。

### 4.4 双因子认证（指纹 + 人脸）
- 流程：**先指纹、后人脸**（都过了才算通过）。
- 指纹是"你有的东西"（物理指纹），人脸+活体是"你本身的样子"（生物特征+活体），两个因子叠加，**代签几乎不可能**（既要有他的手指，又要有他的脸，还得是活的）。

### 4.5 语音播报（TTS + 蓝牙音频链路）
- **语音文件**：预生成 WAV（用 Windows 离线 TTS 生成，不依赖网络）。
- **播放链路**：Python pygame 打开音频 → ALSA 混音器 → BlueALSA 把音频送到蓝牙音箱（A2DP 协议）→ 音箱发声。
- **特制语音**：开机欢迎、签到/签退旋律+语音、当天第一位"早起的鸟儿有虫吃"、21 点后"辛苦了晚安"、时段结束前 1 分钟**放大音量**提醒"请及时签退"。
- **放大音量原理**：提醒播放前把 bluealsa 音量临时调到 85%，播完恢复，吸引注意。

### 4.6 窗口打卡 / 时长计算规则
- 两种模式：
  - **无限次**：比赛演示用，随时签到/签退，时长=签退-签到；
  - **日常（窗口）**：4 个时段（07:30-10:00 / 10:15-13:30 / 14:00-18:00 / 18:30-22:30），每天最晚签退 23:00。
- 规则：段内签退按时长；两段之间签退只算到段截止；超过两段间隔签退有效时长=0（但算签退，下一次才签到）；不在时段内禁止打卡。
- 周统计按"有效时长"累计，排行榜按时长排序——**直接展示修正后的时长，不让自己算**。

### 4.7 数据存储（SQLite）
- `users`：用户表（姓名、角色、微信 openid）
- `face_samples`：人脸特征向量（每人多行）
- `fingerprints`：指纹槽位映射（fp_id → user_id）
- `records`：打卡记录（含有效时长 duration）
- `activity_log`：操作日志
- `settings`：打卡模式/时段配置

## 5. 数据流与工作流程

### 5.1 打卡流程（核心）
```
1. 用户在 K210 前 → K210 摄像头 QVGA 取帧 → YOLO2 检测到人脸
2. K210 蜂鸣器"哔哔" + LCD 提示"FACE! SHAKE"
3. K210 通过串口发 TRIGGER 给树莓派
4. 树莓派：
   a. 若有 AS608：语音"请按指纹"→ 等手指 → 指纹比对
      → 通过 → 继续；不通过/超时 → 拒（发 FAIL）
   b. 语音"请左右摇头" → CSI 摄像头连拍 10 帧（720p）
   c. 人脸识别：检测/关键点 → 提 128 维特征 → 与数据库 1:N 比对
   d. 活体：鼻尖 x 轨迹判断是否摇头
   e. 打卡逻辑：判断签到/签退、是否在可打卡时段
   f. 写库（记录+照片+时长）→ 语音播报"签到成功/签退成功"
5. K210 收到 OK → LCD 显示 in/out 图 + 蜂鸣器成功音
   收到 FAIL → LCD 提示 + 蜂鸣器 3 声 + 冷却 5 秒
```

### 5.2 录入流程（统一录入：人脸+指纹）
```
1. K210 主界面进"录入信息" → 发 ENROLL_START
2. 树莓派生成自动编号（如 5）→ 显示在 K210 顶部
3. 人脸：Pi 拍照 → 发 JPEG 到 K210 显示 → K210 上 KEY 选择 重拍/确认/取消
   → 共 3 张确认 → 每张在 Pi 提特征入库
4. 若有 AS608：语音"请按下手指"→ 按第 1 次 → "请再按一次" → 按第 2 次
   → 模块生成模板 → 存入空闲槽位 → 绑定到该用户 → 语音"指纹录入成功"
5. K210 显示 DONE → 回主界面
（无 AS608 则只录人脸，屏幕提示"无指纹模块"）
```

### 5.3 排行榜/打卡时段流程
- K210 进"排行榜" → 发 RANK:页码 → Pi 生成排行榜图片(320×240 JPEG) → 串口发回 → K210 显示，短按翻页/长按退出；
- K210 进"打卡时段" → 发 WINDOWS → Pi 把模式/时段以 TXT 行发回 → K210 显示。

### 5.4 小程序/桌面端数据流
- 小程序：绑定 openid → 调 API（/api/me、/api/weekly、/api/stats、/api/records、/api/presence…）→ 看周统计、明细、照片、排行榜、在场人数；
- 桌面端：录入管理（新建/补录/录指纹/重命名/删除）+ 数据看板 + 打卡设置 + 导出 Excel。

### 6.2 K210 端：`k210_main_standalone.py`（重点解读）

K210 上跑的是 MaixPy（MicroPython 的 K210 版），文件烧录在 K210 的 flash 里，开机自动运行。

**① 硬件初始化（引脚映射）**
```python
BUZZ_PIN = 9      # 蜂鸣器引脚
KEY_PIN  = 16     # 按键引脚
UART_TX_PIN = 6   # 串口发送引脚 → 接 USB-TTL → 树莓派
UART_RX_PIN = 7   # 串口接收引脚
fm.register(BUZZ_PIN, fm.fpioa.GPIO0)          # 把引脚9映射成GPIO0(蜂鸣器)
fm.register(KEY_PIN,  fm.fpioa.GPIO1, force=True)
fm.register(UART_TX_PIN, fm.fpioa.UART1_TX, force=True)  # 引脚6→UART1发送
fm.register(UART_RX_PIN, fm.fpioa.UART1_RX, force=True)  # 引脚7→UART1接收
uart = UART(UART.UART1, 115200, 8, None, 0, read_buf_len=4096)
```
> 解释：K210 的引脚是可复用的（FPIOA 矩阵），一个引脚可以映射成 GPIO、UART、I2C 等不同功能，用 `fm.register` 指定。`read_buf_len=4096` 加大串口缓冲，避免大图传输时丢数据（这是踩过的坑）。

**② 蜂鸣器驱动（5kHz 方波）**
```python
def beep(times):
    for _ in range(times):
        end = time.ticks_ms() + 200
        while time.ticks_ms() < end:
            buzzer.value(1); time.sleep_us(100)
            buzzer.value(0); time.sleep_us(100)   # 100us翻转 = 5kHz方波
        time.sleep_ms(150)
```
> 解释：经过实测，这个板载蜂鸣器是**无源蜂鸣器**，给它直流不会响、只"嗒"一下；要给它**特定频率的方波**才会发出声音。我们扫频测试 1k~6kHz，5kHz 最响，所以用 100us 高/低电平交替（即 5kHz）。

**③ 串口协议（与树莓派的"对话语言"）**
```python
def recv_line(timeout_ms):   # 按行接收(以 \n 结尾)
def recv_bytes(n, timeout_ms): # 接收 n 个字节(用于接收图片)
```
> 解释：K210 和树莓派之间用**自定义文本协议**，每个命令一行、以换行符结尾，图片用"长度+原始字节"：
> - K210 → Pi：`TRIGGER`（有人脸）、`ENROLL_START`（进录入）、`RANK:1`（要排行榜）、`WINDOWS`（要时段）、`RETRY/CONFIRM/SKIP/ABORT`（录入选择）
> - Pi → K210：`IMG:<长度>\n` + 图片字节（发照片）、`TXT:文字`（显示文字）、`OK:in`（签到成功）、`FAIL`、`CLOSE`（脸太近）、`DONE`（录入完成）
>
> 串口缓冲设计：接收行时把字节攒在 `_rx` 里，找到换行符就切出一行。**注意**：发完选择指令后只清 `_rx`、不读串口——因为一旦读了串口，就可能把 Pi 马上回传的图片吞掉（这是录入卡死的根因，已修复）。

**④ 主面板（KEY 导航）**
```python
idx = 0                       # 当前高亮项 0打卡/1录入/2排行榜/3时段
while True:
    ev = poll_key_event()     # 轮询按键
    if ev == 'short': idx = (idx + 1) % 4      # 短按：切换
    elif ev == 'long': enter_mode(idx)         # 长按：进入
    time.sleep_ms(30)
```
> 解释：主界面用**按键导航**（短按切换、长按进入），触摸功能因硬件不稳定已全局移除。面板图只解码一次缓存，选项变化才重绘（省 CPU、防卡）。

**⑤ 打卡模式（检测→触发→等结果）**
```python
img = sensor.snapshot()                 # 取一帧
objs = kpu.run_yolo2(task, img)         # KPU 跑 YOLO2 人脸检测
if not objs: continue                    # 没人脸就继续
beep(2); uart.write(b'TRIGGER\n')        # 检测到→蜂鸣器+通知Pi
# 等 Pi 回 OK/FAIL/CLOSE（最长60秒）
```
> 解释：K210 的 YOLO2 模型在 KPU 上跑，检测到人脸就发 `TRIGGER`，然后**阻塞等 Pi 的裁决**。为避免 CPU 空转和按键不响应，检测做了 200ms 节流。

**⑥ 录入模式（显示 Pi 发的照片 + 选择）**
```python
line = recv_line(15000)                  # 等 Pi 发 IMG:长度 行
data = recv_bytes(n, 20000)              # 收图片字节
open('/flash/tmp.jpg','wb').write(data)  # 写临时文件
img = image.Image('/flash/tmp.jpg')      # 解码JPEG
lcd.display(img)                         # 显示
del img; gc.collect()                    # 释放内存
# KEY: 短按切换 重拍/确认/取消, 长按执行
choice = enroll_menu_tap(sample, idx)
uart.write((choice + '\n').encode())     # 把选择回给Pi
_rx = b''                                # 只清缓存, 不读串口(关键!)
```
> 解释：照片由 Pi 拍好后通过串口发来，K210 只负责**显示和让用户选择**，照片本身不需要保存在 K210（Pi 那边保存）。内存释放用 `del` + `gc.collect()`，进入模式时还释放面板缓存图腾出约 150KB。

### 6.3 树莓派端：`k210_link.py`（联动服务，重点解读）

这是一个常驻服务（systemd 开机自启），核心是**主循环：读串口命令 → 执行 → 回结果**。

**① 串口识别（K210 vs 指纹）**
```python
def detect_ports():
    ports = find_serial_ports()          # /dev/ttyUSB* /dev/ttyACM*
    if len(ports) < 2:                   # 只有K210 → 不探测指纹
        return open_serial(ports[0]), None
    for p in ports:                      # 逐个问"你是AS608吗?"
        f = as608.AS608(p, baud=57600)
        if f.verify_password():          # 响应指纹协议 → 这就是指纹
            fp = f
        else:
            rest.append(p)               # 剩下的给K210
    return k210_ser, fp
```
> 解释：用 **AS608 的握手协议**去"点名"，谁应答谁就是指纹模块；K210 不应答，所以绝不会搞混。单个串口时绝不探测（避免给 K210 发垃圾）。

**② 打卡主流程**
```python
if cmd == b'TRIGGER':
    user = None
    if fp is not None:                        # 有指纹→先指纹
        voice.play('fp_please'); code, fid = fp.verify(timeout=10)
        if 通过: user = 该指纹的用户
        else: FAIL; continue                   # 指纹不过直接拒
    voice.play('shake_please')                 # 提示摇头
    frames = capture_burst()                   # CSI 连拍10帧
    result, err = process_burst(frames, ...)   # 识别+活体+打卡
    if result.ok: voice 签到成功/签退成功; 回 OK
    else: 按错误类型播不同语音; 回 FAIL/CLOSE
```
> 解释：这就是"双因子"的落地：**指纹优先**（模块在就必须要指纹过），然后**人脸+摇头活体**，都过才算。每步都有语音提示（请按指纹/请左右摇头/签到成功…）。

**③ 统一录入（人脸+指纹）**
```python
def run_enroll_session(k210, fp):
    name = attendance.next_number_name()   # 自动编号 1,2,3...
    # 人脸3张：拍照→IMG发给K210→等 确认/重拍/取消
    # 3张确认后：
    _finish_fp(k210, fp, user, name, txt)  # 有指纹→自动录指纹
        slot = attendance.next_fp_slot()
        voice.play('fp_press')
        fp.enroll(slot, on_first=语音"再按一次", on_again=...)
        attendance.add_fingerprint(user['id'], sid)
        voice.play('fp_enroll_ok')
```
> 解释：一个"录入信息"入口完成**人脸+指纹**，先人脸后指纹，指纹录入时语音提示按两次手指。无人脸样本或没指纹模块则跳过指纹。

### 6.4 树莓派端：`face_engine.py`（人脸识别引擎）
- `detect_faces(bgr)`：MediaPipe FaceDetector 出人脸框。
- `face_landmarks(bgr)`：MediaPipe FaceLandmarker 出 478 个关键点。
- `get_embedding(face_bgr)`：face_recognition（dlib）提 **128 维特征**。
- `compare(emb, ref)`：欧氏距离（越小越像）。
- `get_embedding_multi`：多尺度容错（HOG → CNN 兜底）。
- `blink_ratio / is_blinking`：EAR 眨眼检测。
- `nose_x / head_shake_detected`：鼻尖轨迹摇头活体检测。

### 6.5 树莓派端：`attendance.py`（数据层）
- 建表（用户/人脸样本/指纹映射/记录/日志/设置），幂等兼容。
- `next_kind`：判断这次是签到还是签退（按模式+时段规则）。
- `punch`：写入记录 + 计算有效时长（窗口模式）。
- `weekly_summary`：周统计 + 排名。
- `current_presence`：在场人数。
- `delete_face / delete_fp / next_fp_slot`：人脸/指纹独立管理。

### 6.6 树莓派端：`app.py`（Flask API）
- 提供 RESTful 接口（约 23 个）：健康检查/打卡/录入/绑定/我的/周统计/排行榜/记录/在场/日志/设置/删除/指纹录入等，JSON 格式，供小程序和桌面端调用。
- 指纹录入接口：检测到 AS608 才初始化语音，**跳过 K210 端口**扫描，避免串扰。

### 6.7 树莓派端：`as608.py`（指纹驱动）
- 按 AS608 协议组包/解包（帧头 0xEF01 + 校验和）。
- `verify()`：等手指 → 采图 → 生成模板 → 1:N 搜索，返回槽位号。
- `enroll(slot)`：按 2 次手指 → 两个模板 → RegModel 合并 → Store 存槽位。

### 6.8 树莓派端：`voice.py`（语音模块）
- `init()`：初始化 pygame 混音器，设置 XDG_RUNTIME_DIR 和 ALSA 配置指向蓝牙音箱。
- `play(name)`：非阻塞播单条。
- `play_seq([...])`：后台线程顺序播放（旋律+语音）。
- `play_loud(name)`：临时放大音量到 85% 播完恢复（时段提醒用）。
- 无音频设备时静默降级，绝不影响打卡主流程。

## 7. 硬件与软件联调（对接方式）

> 答辩时这段很关键：**不是讲软件功能，而是讲"硬件和软件是怎么对接起来的"**。

### 7.1 物理接线
```
树莓派5  ◄──USB──  USB-TTL①(CH340)  ◄──UART(TX6/RX7)──  K210
树莓派5  ◄──USB──  USB-TTL②(CH340)  ◄──UART(57600)──  AS608指纹
树莓派5  ◄──CSI排线──  OV5647摄像头
树莓派5  ◄──蓝牙A2DP──  自制蓝牙音箱(MH-M18)
```
- 串口设备在 Linux 里是 **/dev/ttyUSB0、/dev/ttyUSB1**（按插入顺序），程序用 glob 扫描识别。
- **共地**：串口模块与设备要共地（GND 相连），否则电平不稳。

### 7.2 串口协议对接（软硬件的"共同语言"）
| 方向 | 命令 | 含义 |
|---|---|---|
| K210→Pi | `TRIGGER` | 检测到人脸，请求打卡 |
| K210→Pi | `ENROLL_START` / `RANK:1` / `WINDOWS` | 请求录入/排行榜/时段 |
| K210→Pi | `CONFIRM` / `RETRY` / `SKIP` / `ABORT` | 录入照片的选择 |
| Pi→K210 | `IMG:<长度>` + 字节 | 发送一张 JPEG 图片 |
| Pi→K210 | `TXT:文字` | 显示一行文字（编号/状态/指纹提示） |
| Pi→K210 | `OK:in` / `OK:out` / `FAIL` / `CLOSE` / `DONE` | 打卡结果 / 录入完成 |

- **协议设计要点**：文本行 + 长度前缀，简单可靠；图片二进制用"长度+数据"避免歧义。
- **同步机制**：K210 发请求后阻塞等 Pi 响应（带超时），Pi 收到命令同步执行后回结果，天然一问一答。

### 7.3 识别到哪一层
- **硬件层**：K210（检测）、AS608（指纹采图/比对）、摄像头（抓拍）、音箱（发声）。
- **软件层**：MediaPipe/dlib（识别）、Flask（接口）、SQLite（存储）、pygame/bluealsa（音频）。
- **对接点**：串口（K210↔Pi）、USB 串口（AS608↔Pi）、HTTP（Pi↔小程序）、蓝牙 A2DP（Pi↔音箱）。

### 7.4 踩过的联调坑（答辩可以讲，体现工程能力）
1. **录入卡死**：发完选择后 `uart_flush()` 把 Pi 回传的图片吞了 → 改为只清缓存不读串口；
2. **蜂鸣器不响**：无源蜂鸣器需要 5kHz 方波，扫频找到最响频率；
3. **串口串扰**：探测 AS608 时误发给 K210 垃圾 → 单串口不探测 + 记录 K210 端口跳过；
4. **服务重启卡死**：pygame 占音频导致 SIGTERM 不退 → 加信号兜底；
5. **systemd 无桌面环境**：bluealsa 需要 XDG_RUNTIME_DIR → 程序自动补环境变量。

## 14. 常见答辩问题准备

**Q1：人脸识别和活体检测原理是什么？**
A：识别=把人脸压缩成 128 维特征向量，用欧氏距离和库里比；活体=用关键点追踪鼻尖，判断有没有"左右摇头"（照片不会动）。

**Q2：为什么不用纯云端方案？**
A：现场可能无网；数据本地化更隐私、更快、更便宜，且完全离线可用。

**Q3：K210 和树莓派为什么分工？**
A：K210 便宜低功耗、自带 KPU 适合端侧轻量检测；树莓派算力强、生态好，适合跑识别/数据库/API/语音。端云协同降成本提可靠。

**Q4：指纹怎么防伪造？**
A：AS608 是光学指纹，识别的是活体指纹的脊线特征；配合"指纹+人脸+活体"双因子，伪造难度极高。

**Q5：多人同时打卡会怎样？**
A：抓拍时取最大人脸框，优先处理最近/最大的人；当前设计为单机单队列，适合小批量（课堂/小组）。

**Q6：数据存哪里？安全吗？**
A：SQLite 存在树莓派本地，人脸特征/指纹映射/打卡记录全本地，不上传第三方；小程序只通过局域网 API 读取。

**Q7：如果断电/断网会怎样？**
A：断电重启后服务自动拉起；断网完全不影响打卡，数据本地累积。

**Q8：成本多少？**
A：核心硬件（K210、树莓派、指纹、音箱、USB-TTL）约 150 元内，远低于商用考勤机。

**Q9：现场如果识别失败怎么办？**
